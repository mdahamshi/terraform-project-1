# Terraform Project 1 — AWS IAM Users & Roles

Manages AWS IAM users, login profiles, and role-based access control using Terraform. User definitions are stored in a YAML file, and Terraform dynamically creates IAM users, assigns roles, and configures assume-role policies based on those definitions.

> **Note:** Passwords are output to the console for learning purposes only. This is not production-safe practice.

## Key Features

- **Data-driven IAM management** — users and role assignments defined in `users.yaml`, not hardcoded in `.tf` files
- **Dynamic role creation** — roles and their assume-role policies are generated from a `locals` block, supporting easy expansion
- **Policy attachment** — maps AWS managed policies to custom roles automatically
- **Login profile provisioning** — creates console login profiles for each IAM user with auto-generated passwords
- **YAML-to-Terraform pipeline** — uses `yamldecode()` to read external config, separating data from infrastructure logic

## Configuration

### Users

Edit `users.yaml` to define users and their role assignments:

```yaml
users:
  - username: sarah
    roles: [readonly, developer]
  - username: amenah
    roles: [admin, auditor]
  - username: mohammad
    roles: [readonly]
```

### Roles

Role definitions and their associated AWS managed policies are defined in `locals` inside `roles.tf`:

| Role | Policies |
|---|---|
| `readonly` | `ReadOnlyAccess` |
| `admin` | `AdministratorAccess` |
| `developer` | `AmazonVPCFullAccess`, `AmazonEC2FullAccess`, `AmazonRDSFullAccess` |
| `auditor` | `SecurityAudit` |

### Provider

The AWS region is set in `provider.tf`. Change `eu-west-1` to your desired region:

```hcl
provider "aws" {
  region = "eu-west-1"
}
```

## Deployment

This is a local Terraform project with no remote state backend or CI/CD pipeline configured. All state is stored locally in `terraform.tfstate`.

To deploy to a different AWS account or region:

1. Update credentials via `aws configure` or environment variables
2. Change the region in `provider.tf`
3. Run `terraform init && terraform apply`

> **Tip:** For team or production use, configure a [remote backend](https://developer.hashicorp.com/terraform/language/backend) (e.g., S3 + DynamoDB) and store sensitive values in a secrets manager.
